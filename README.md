# Build Sheet 改裝帳本

給機車改裝玩家的記帳與展示工具。單一 HTML 檔，開啟即用，不需註冊。

**線上使用：** https://77456-ouo.github.io/buildsheet/

---

## 一、核心概念：一份資料，兩種視圖

使用者只維護一份零件清單，系統將它渲染成兩種完全不同的介面。

| 模式 | 對象 | 內容 |
|------|------|------|
| **紀錄模式** | 對內，自己看 | 統計卡、各系統投入圖、零件增修刪、篩選搜尋。顯示金額 |
| **展示模式** | 對外，分享給車友 | Build Sheet 版面，依前後段分節、可掛照片與調校備忘。**不顯示金額** |

任一邊的修改即時反映到另一邊，永遠不需要維護第二份清單。展示層擁有自己的設定（區塊順序、單品可見度、封面照），但這些設定只影響呈現，不觸碰帳本資料。

## 二、功能

### 2.1 分類與位置

五大分類：**制動、懸吊、動力、外觀、其他**。設計原則是「分類是給統計看的，不是給描述用的」，描述交給品項名稱。

分類之外另設一個選填的**位置**屬性（前段／後段），它只負責展示模式的排版分節，因為看車的人是從車頭掃到車尾，完全不影響統計。

### 2.2 完工價與附加費用

金額欄位以**完工價**為單位，符合台灣車行連工帶料報價的習慣。

針對事後發生的客製加工與調校工資（例如前叉內管送廠加工、ECU 撰寫），設計了**附加費用**子紀錄：掛在被加工的零件底下，有獨立的名目與金額，統計時自動併入該零件的總花費，展示模式則以「客製」標籤呈現而不露出金額。

### 2.3 狀態生命週期與汰換

每個零件有三種狀態：**願望清單 → 現役 → 已退役**，對應改裝品的完整生命週期。

最關鍵的日常操作**汰換**被設計成單一動作：選定舊零件、填入新零件、順手記下舊件的回收金額，系統一次完成四件事：

1. 新件以現役入帳
2. 舊件轉為已退役
3. 記錄舊件回收金額
4. 舊件自展示頁隱藏

### 2.4 其他

- 願望清單金額獨立統計，不計入已花費
- 零件照片與封面照，上傳時自動壓縮至 1280px、JPEG 品質 0.85
- 可自訂的避震設定備忘卡，調校參數是改裝文化的一部分
- 展示版面可調整區塊順序、單品順序與可見度
- 完工價可留白（填 0），未定價項目單獨計數

## 三、資料架構

### 3.1 儲存機制

資料**只存在使用者自己瀏覽器的 localStorage**，不會上傳到任何伺服器，開發者也看不到。

| 項目 | 內容 |
|------|------|
| 儲存位置 | 瀏覽器 localStorage |
| 鍵值 | `buildsheet.v1` |
| 格式 | JSON 字串 |
| 寫入時機 | 任何變更後 400ms（去抖動） |
| 容量上限 | 約 5MB，由瀏覽器決定 |

超過容量時頁面會顯示明確警告，提示先匯出備份再移除照片。照片以 base64 內嵌，是最主要的空間消耗來源。

### 3.2 資料模型

整份資料由四個實體組成，零件表是唯一的事實來源：

```
snapshot
├── vehicle    車輛銘牌（車名、標語）
├── items[]    零件清單 ← 唯一事實來源
│   └── add[]  附加費用（子紀錄）
├── tune[]     調校備忘（鍵值對清單）
└── layout     展示版面設定
```

### 3.3 欄位定義

**根物件**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `v` | number | 格式版本，目前為 `1` |
| `savedAt` | string | 儲存時間，ISO 8601 |
| `vehicle` | object | 車輛銘牌 |
| `items` | array | 零件清單 |
| `tune` | array | 調校備忘 |
| `layout` | object | 展示版面設定 |
| `nextId` | number | 下一個可用的零件流水號 |

**vehicle（車輛）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `name` | string | 車名，例如「黑頂鶴」 |
| `sub` | string | 英文標語，顯示於車名下方 |

**items[]（零件）**

| 欄位 | 型別 | 必填 | 說明 |
|------|------|------|------|
| `id` | number | ✓ | 流水號，全檔唯一 |
| `b` | string | ✓ | 品牌，未填時為 `—` |
| `n` | string | ✓ | 品項名稱 |
| `p` | number | ✓ | 完工價，`0` 代表未定價 |
| `c` | string | ✓ | 分類：`制動` `懸吊` `動力` `外觀` `其他` |
| `s` | string | ✓ | 狀態：`on` 現役／`wish` 願望清單／`out` 已退役 |
| `d` | string | ✓ | 日期，格式 `YYYY-MM-DD` |
| `pos` | string | | 位置：`F` 前段／`R` 後段／省略為不分區 |
| `rec` | number | | 回收金額，僅退役品有值 |
| `add` | array | | 附加費用清單 |
| `img` | string | | 零件照片，data URI |
| `v` | boolean | | `false` 代表在展示頁隱藏，省略視為顯示 |

**items[].add[]（附加費用）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `t` | string | 名目，例如「電腦撰寫」 |
| `p` | number | 金額 |

**tune[]（調校備忘）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `k` | string | 項目名稱，例如「前叉壓縮側」 |
| `v` | string | 設定值，例如「14 格」。字串型別，可填任意格式 |

**layout（展示版面）**

| 欄位 | 型別 | 說明 |
|------|------|------|
| `catOrder` | array | 五大分類在展示頁的排列順序 |
| `wish` | boolean | 是否顯示「下一步」區塊 |
| `tune` | boolean | 是否顯示調校備忘卡 |
| `cover` | string | 封面照，data URI，無則為 `null` |

### 3.4 備份檔格式

匯出的 JSON 即為上述完整結構：

```json
{
  "v": 1,
  "savedAt": "2026-08-16T17:26:00",
  "vehicle": { "name": "黑頂鶴", "sub": "MANX GREEN PROJECT" },
  "items": [
    {
      "id": 0,
      "b": "aRacer",
      "n": "RC Super X 全取代電腦",
      "p": 18500,
      "c": "動力",
      "s": "on",
      "d": "2026-07-05",
      "add": [{ "t": "電腦撰寫", "p": 3000 }]
    }
  ],
  "tune": [{ "k": "前叉 壓縮側", "v": "14 格" }],
  "layout": {
    "catOrder": ["制動", "懸吊", "動力", "外觀", "其他"],
    "wish": true,
    "tune": true,
    "cover": null
  },
  "nextId": 1
}
```

匯入時會執行正規化：套用舊分類對應、補上缺漏日期、金額轉為數字、重建流水號。因此手動編輯過的檔案只要結構正確就能匯入。

### 3.5 統計計算規則

| 指標 | 計算方式 |
|------|----------|
| 單品總花費 | `p` ＋ 所有 `add[].p` 的總和 |
| 歷史總投入 | 現役品總花費 ＋ 退役品總花費 |
| 現役車上價值 | 現役品總花費 |
| 退役沉沒成本 | 退役品總花費 － 所有 `rec` 的總和 |
| 願望清單待購 | 願望品總花費 |
| 各系統投入 | 依分類加總，**含已退役**，不含願望清單 |

回收金額使「退役沉沒成本」成為扣除二手變現後的淨損失，讓總帳誠實。

### 3.6 分類遷移機制

調整分類定義時**不改寫既有資料**，而是透過一層對應表在載入時轉換：

```js
const LEGACY = { 傳動: '動力', 燈電: '外觀', 操控: '外觀' };
```

早期版本使用八分類，收斂為五分類時僅靠這張表完成遷移。未來若再調整分類，只需擴充此表，不需搬動歷史資料。

## 四、使用方式

1. 開啟網址，按「✎ 車名」設定車名與標語
2. 用表單新增改裝品，點清單任一項可修改或刪除
3. 切換到展示模式，按「✎ 編輯版面」調整順序、可見度與照片
4. 把網址分享給車友，他們看到的是不含金額的 Build Sheet

### 資料備份

**重要的資料請定期用「⬇ 匯出備份」存成 JSON 檔**，換裝置時再用「⬆ 匯入備份」還原。

以下情況資料會消失，請務必先備份：

- 更換手機或瀏覽器
- 清除瀏覽器資料或快取
- 使用無痕模式
- 照片過多導致超出容量上限

## 五、技術

單一 HTML 檔，原生 JavaScript，無框架、無建置流程、無外部相依套件。唯一的外部資源是 Google Fonts 的 Chakra Petch 與 Noto Sans TC 字體。

部署於 GitHub Pages。使用者資料完全留在客戶端，不需要後端。
